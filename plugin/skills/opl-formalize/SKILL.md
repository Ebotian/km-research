# 把猜想形式化

```bash
# 下文用 $OPL 指代插件的 bin 目录。先定位一次——agent 的 cwd 是用户工作区，
# 不是插件目录，所以 `bin/opl-…` 这种写法会找不到命令。
OPL="${KIMI_PLUGIN_ROOT:-<插件根>}/bin"
```

## 第一件事：编译通过不等于陈述正确

这是本技能存在的理由。实测数据：陈述自动形式化的**语义正确率约 76%**，而编译率会
*系统性高估*忠实度——一个改变了原意的陈述照样能编译通过。

所以两条硬规矩：

- 形式化状态在**人工确认前只停在 `compiles`**，不得写成 `faithfulness_checked`。
- 本技能产出的是**待审的形式化**，不是「已完成的形式化」。措辞上不要含糊。

## 流程

### 1. 先把原命题冻结成文字

把命题与**全部前提**写成一段自然语言，存进台账。这一步不做形式化——它是后面判定
「有没有改变原意」的唯一基准。

```bash
$OPL/opl-conj add --id C-0001 --title "短标题" \
  --statement "<含全部前提的原命题>" --source "<出处 URL 或文献>"
```

### 2. 写 Lean 陈述骨架，先不写证明

目标只是「陈述能编译」。用 `sorry` 占位是正常的、预期之内的。

```lean
import Mathlib

theorem opl_C0001 : ∀ n : ℕ, 1 < n → <结论> := by sorry
```

### 3. 跑审计，拿诊断

```bash
$OPL/opl-leancheck --file lab/lean/C0001.lean --decl opl_C0001
```

- `SORRY_AX` 是**预期**的（用了 sorry 占位）
- `FAILED` 表示陈述本身有语法或类型错误，诊断会指到具体行
- `PROVED` 不应该出现——陈述骨架不可能已被证明

### 4. 过一遍忠实度检查清单（不可省）

**每一条都要在回答里明确写出判断**，不能沉默。沉默等于没检查。

| # | 检查项 | 问自己 |
|---|---|---|
| 1 | 量词顺序与作用域 | `∀ε ∃N ∀n` 与 `∃N ∀ε ∀n` 不是一回事，写的是哪一个？ |
| 2 | 隐含前提 | 非空、有限、非退化、元素互异——原文默许的前提有没有显式写出来？ |
| 3 | 数系边界 | `ℕ` 从 0 还是 1？`ℤ` 的减法会截断？`ℝ` 的除法需要非零？边界值 `n=0` 成不成立？ |
| 4 | 严格与非严格 | `≤` 还是 `<`？`ε > 0` 还是 `ε ≥ 0`？原文用的是哪个？ |
| 5 | 有限与无限 | 「所有 n」指所有自然数，还是某个有限范围？写成 `∀ n < N` 就改变了命题 |
| 6 | 蕴含方向 | `→` 的左右有没有写反？前提有没有被写成结论？ |
| 7 | 模糊量词 | 原文里的「足够大」「几乎所有」「一般地」被翻译成了什么确定的东西？ |
| 8 | 存在性的种类 | `∃` 就够了，还是需要一个可构造的见证？ |
| 9 | 平凡化 | 有没有退化情形（空集、单元素、`n=0`）让命题恒真？恒真的陈述没有信息 |
| 10 | 与出处对照 | 逐条对着 `--source` 指向的原文核一遍，而不是凭记忆 |

第 7 条最容易出事：把原文的「足够大」翻译成某个具体常数，就引入了一个原文没有的
断言。正确做法是保留为 `∃ N, ∀ n ≥ N, …`，并在回答里指出原文措辞模糊。

### 5. 停在这里，交人确认

```bash
# 只推进到 compiles —— faithfulness_checked 是人工确认项
$OPL/opl-conj set C-0001 --formalization-status compiles \
  --evidence lab/lean/C0001.lean
```

工具**拒绝**在没有签字的情况下写 `faithfulness_checked`（退出码 `2`）——那是刻意的，
不是可以绕过的流程。第 1–4 步的复核做完之后，由人签字：

```bash
$OPL/opl-conj set C-0001 --formalization-status faithfulness_checked \
  --confirmed-by "谁" --confirmation-note "逐条对过那十条清单，第 7 条按 ∃N 保留"
```

签字会记进独立的 `human_confirmations`，**不与机器判决混在同一列**。理由就是这张
清单的意义：编译通过看不出那 24% 的语义偏差，而「谁确认的」必须可查。

## 已经踩过的坑

- **`#print axioms` 在没有公理时打印的是 `'t' does not depend on any axioms`**，
  不是 `depends on axioms: []`。靠「没有输出」判断「没信息」会误判。
- **`sorry` 与 `native_decide` 都退出码 0**。所以陈述骨架的审计不能只看退出码。
- **`import Mathlib` 每次约 2.2 秒**（`import Init` 约 0.5 秒）。迭代陈述时用最小
  导入；只有在需要具体定理时才上 Mathlib。
